# About the Joshternet

The Joshternet is a real open-web experiment built around an objectively silly premise:

**What if the Internet had an actual network for Joshes?**

That question is funny on purpose. The attempt to answer it is serious.

## It started with an unreasonable number of Joshes

Joshua Morris conceived and started the Joshternet after several observations came together.

There are a remarkable number of people named Josh or Joshua in technology and on the web. Many Joshes have built notable software, companies, websites, standards, tools, communities, and other things.

Joshua Morris is also a Josh.

Once `Josh`, `joshing`, and `joshing around` entered the same design space, the premise became difficult to resist. Joshes could josh other Joshes. A Josh could ask whether another Josh was really a Josh. The Internet could have a Josh network.

It was ridiculous enough to be interesting and specific enough to build.

## The premise is ridiculous

**The premise is ridiculous. The architecture does not have to be.**

A network of Joshes is funny. Identity, participation, interoperability, independent ownership, decentralization, discovery, governance, and trust are real engineering and community-design problems.

Instead of stopping at a joke website or centralized directory, the Joshternet asks what happens when the premise is treated seriously using open-web principles.

That decision led to RFC-style specifications, self-declared identity, `/.well-known/josh`, independently controlled websites, decentralized participation, and ordinary web standards.

The humor is part of the project. It is not an excuse for sloppy architecture.

## Why Joshes?

There is no grand philosophical justification.

The project begins with Joshes because its creator is a Josh, many Joshes are visible in technology and on the independent web, and the Josh-and-joshing language makes the community unusually good territory for a playful experiment.

It also provides a real, recognizable community instead of an abstract hypothetical user base.

That specificity is useful. The Joshternet is not a generic protocol with Josh branding added afterward. It should solve real problems for an actual community and learn from actual implementations.

The Joshternet remains specifically the Joshternet.

## Why independent websites?

The web already provides the independent places.

People can control their own domains, websites, content, publishing tools, hosting, and infrastructure. The Joshternet should add conventions between those places rather than replace them.

Participation should not require someone to surrender:

- their domain;
- their website;
- their content;
- their publishing tools;
- their hosting;
- their infrastructure.

A participant should not have to become a tenant of a Joshternet platform.

The sites should continue to belong to the people who operate them.

## Serious standards for a silly network

The use of RFC-style specifications and a `/.well-known/` resource is intentional.

The [current specifications][specifications] define small representations and explicit semantics. The [implementation guide][implementation] shows how little an independently operated site needs in order to publish the current participation declaration.

The project prefers boring protocols, small representations, existing web standards, understandable implementations, and independently deployable sites over proprietary infrastructure.

The joke should not become an excuse for vague behavior or incompatible implementations.

The standards work should also not become so self-serious that the project forgets why it is called the Joshternet.

## The network is not this website

No single website, organization, registry, crawler, directory, server, or implementation should be necessary for the Joshternet itself to exist.

joshternet.org documents the project. It is not the network.

The GitHub organization hosts project development. It is not the network.

Joshua Morris started the project. He is not the network.

The participating sites and interoperating infrastructure form the network. The protocol matters more than any particular implementation.

[RFC-JOSH-0000][rfc-0000] establishes the decentralization principle more formally.

## Build the Josh network first

The project starts with a concrete rule:

Build the Josh network first.

Learn from actual implementations.

Generalize only what reality proves reusable.

Real participants expose real problems. Working implementations expose ambiguity. Actual use shows which interoperability requirements matter and which ideas only looked useful in the abstract.

No generic community-network standard exists today.

The project remains **PRE-JOSH**. Its three current RFCs are Drafts, and none have been Accepted. This is an experiment being built in public, not an established standards organization speaking for a finished community.

## The larger experiment

The broader question is whether a recognizable community can define enough shared open conventions to recognize participation, connect independent sites, and evolve together without creating another centralized platform.

The Joshternet explores whether independently controlled websites, voluntary participation, self-declared identity, open specifications, ordinary web protocols, and replaceable infrastructure can support that kind of community.

It is building one concrete example and seeing what works. It is not arguing that every community must operate this way.

If the experiment produces useful conventions, architectural ideas, or open implementations, another recognizable community should be able to study them, adapt them, define its own identity and participation rules, and operate independently.

That community should not need permission from the Joshternet or registration with the Joshternet. It would not become a subdivision of the Joshternet.

The Joshternet remains the Joshternet.

The joke is specific. Any useful lessons do not have to be.

The [Joshternet specification repository][spec] is the canonical source for the current specifications.
